# Step 4 Report

## 목적

방 생성, 멤버 조회, 초대 토큰 발급/재발급, 토큰 기반 참가 기능을 추가하고, 방 리소스 접근을 `RoomMember` 기준으로 통일한다.

## 적용 내용

- 방/멤버 엔티티 생성 흐름 보강
  - `Room.create(...)`: 방 생성 시 이름과 소유자를 명확하게 담아 엔티티를 만들기 위한 정적 팩토리 메서드이다.
  - `RoomMember.create(...)`: 방 참가 시 어떤 방과 어떤 사용자를 연결하는지 명확하게 표현하기 위한 정적 팩토리 메서드이다.
  - 방 생성 시 소유자를 자동으로 `RoomMember`에도 추가했다. 이렇게 해야 소유자도 동일한 멤버 권한 검사 흐름을 그대로 탈 수 있다.

- 리포지토리 추가
  - `RoomRepository`: 방 저장/조회에 사용한다.
  - `RoomMemberRepository`: 특정 사용자가 특정 방의 멤버인지 확인하고, 방 멤버 목록을 조회하는 데 사용한다.
  - `RoomInviteTokenRepository`: 방별 현재 초대 토큰 조회, 토큰 문자열 기반 조회, 토큰 중복 방지에 사용한다.

- 초대 토큰 엔티티 추가
  - `RoomInviteToken`: 방별 현재 유효한 초대 토큰 1개를 관리한다.
  - 토큰 문자열과 만료 시각 `expiresAt`을 저장한다.
  - `reissue(...)` 메서드로 같은 방의 토큰을 새 문자열과 새 만료 시각으로 교체할 수 있다.
  - 사용 횟수를 세지 않기 때문에 하나의 유효 토큰으로 여러 사용자가 참가할 수 있다.

- 초대 토큰 생성 방식 추가
  - `InviteTokenGenerator`: `SecureRandom` 기반으로 32바이트 난수를 만들고 URL-safe Base64로 인코딩한다.
  - 충분한 엔트로피를 가진 예측 불가능한 토큰을 만들기 위한 구성이다.
  - 토큰 충돌 가능성은 매우 낮지만, 저장 전에 중복 확인을 한 번 더 수행하도록 했다.

- 방 권한 검사 공통화
  - `RoomAuthorizationService.checkMember(roomId, userId)`: 방이 존재하는지 확인한 뒤, 해당 사용자가 `RoomMember`인지 검사한다.
  - 방이 없으면 `NOT_FOUND`, 방은 있지만 멤버가 아니면 `FORBIDDEN`을 반환한다.
  - 방 멤버 조회와 초대 토큰 발급 API는 모두 이 공통 검사 메서드를 사용한다.

- 방 서비스/컨트롤러 추가
  - `POST /api/rooms`: 인증된 사용자가 새 방을 만든다.
  - `GET /api/rooms/{roomId}/members`: 방 멤버 목록을 조회한다. 각 멤버에 대해 `owner` 여부도 함께 내려준다.
  - `POST /api/rooms/{roomId}/invite-token`: 방의 현재 초대 토큰을 새로 발급한다. 이미 토큰이 있어도 새 토큰으로 교체되므로 재발급 역할까지 함께 수행한다.
  - `POST /api/rooms/join?token=...`: 유효한 토큰으로 방에 참가한다.

- 초대 토큰 정책 반영
  - 만료 기간은 7일로 고정했다.
  - 재발급 시 이전 토큰은 더 이상 사용할 수 없도록 현재 토큰 값을 교체한다.
  - 같은 토큰으로 여러 사용자가 참가할 수 있도록 사용 후 폐기하지 않는다.
  - 이미 멤버인 사용자가 다시 참가 요청을 보내면 중복 멤버를 만들지 않고 `joined=false`로 응답한다.

- 테스트 추가
  - 방 생성 시 소유자가 자동으로 멤버가 되는지 검증했다.
  - 비멤버의 멤버 조회 요청이 `403 FORBIDDEN`으로 막히는지 검증했다.
  - 초대 토큰 재발급 시 이전 토큰이 무효화되는지 검증했다.
  - 하나의 토큰으로 여러 사용자가 참가할 수 있는지 검증했다.
  - 만료된 토큰으로 참가할 수 없는지 검증했다.

## 메모

- 이번 단계에서는 `POST /api/rooms/{roomId}/invite-token`를 호출할 때마다 새 토큰을 발급하도록 구현했다.
- 현재 권한 모델에는 역할 구분이 없으므로, 요구사항에 맞춰 방 리소스 접근 권한은 `RoomMember` 여부로 통일했다.
