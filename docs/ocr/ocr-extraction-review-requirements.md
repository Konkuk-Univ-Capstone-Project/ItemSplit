# 한국어 영수증 OCR 추출 및 인식 결과 수정 화면 요구사항

## 1. 목적과 적용 기준

한국어 영수증 사진에서 정산에 필요한 품목과 금액을 추출하고, 사용자가 사진과 비교해 수정한 결과만 정산 데이터에 반영한다. 인식 서비스는 NAVER CLOVA 영수증 OCR을 사용한다. OCR은 입력을 돕는 기능이며 자동 정산 확정 기능이 아니다.

이 문서는 화면 표시·사용자 검토·편집 동작을 정의한다. 정책·DB·API의 최종 기준은 [OCR 상태·DB·API 최종 설계](state-db-api-design.md)이며, 공급자 호출과 응답 매핑은 [CLOVA OCR 연동 설계](clova-ocr-integration-design.md)를 따른다. 이미지 저장 조건은 [S3 저장 설계](../storage/image-storage-design.md)를 따른다. 설계 채택은 구현 완료를 뜻하지 않는다.

[공통 API·DB 계약](../api-db-contract.md)의 금액 상한·멤버 ID·원자적 저장 규칙은 유지한다. 총액 입력·불일치 정산 차단, 수정 권한, 재인식 흐름은 최종 설계의 변경안을 우선한다. 공통 계약에 이전 정책이 남아 있더라도 이 화면에서 총액 입력이나 총액 차이에 따른 정산 차단을 다시 도입하지 않는다.

| 항목 | 적용 기준 |
|---|---|
| 서버가 받는 이미지 | JPEG·PNG, 장당 최대 10MB |
| 기타 입력 형식 | HEIC·HEIF·WEBP는 화면에서 JPEG로 변환 후 업로드. 변환 불가능한 파일은 설명과 재선택 기능 제공 |
| 이미지 장수 | 영수증당 최대 3장, 한 장씩 업로드하고 저장된 순서로 처리 |
| 저장·조회 | 비공개 저장소, `receipt_images`의 `imageId`로 식별, 방 멤버만 접근 |
| 이미지 미리보기 | 이미지 목록 API가 발급하는 단기 URL 사용. URL을 영구 식별자로 저장하지 않음 |
| 보관 | 영수증·방 삭제 시까지 유지. 이미지 개별 삭제는 인식 시작 전만 가능. OCR 반영 완료만으로 삭제하지 않음 |
| 구현 범위 | 인쇄된 한국어 영수증, 원화 정수 금액, 같은 영수증을 나눠 촬영한 사진 |
| 범위 밖 | 서로 다른 영수증 자동 분리, 손글씨 보장, 외화 환산, 할인 자동 배분, 환불 정산, 공급자별 원문 응답을 그대로 품목으로 저장 |

임시 보관 후 자동 삭제 정책으로 바꾸려면 저장 설계와 최종 계약을 함께 변경한다. ‘원본 미리보기’는 서비스에 업로드된 이미지를 뜻하며, JPEG 변환 이전 HEIC 원본 보존을 뜻하지 않는다.

### 사용자별 동작

- 업로더 기록이 있는 이미지 영수증에서는 방 멤버 누구나 이미지·작업·초안을 조회할 수 있다. 이미지 추가·삭제, 인식 시작·실패 사진 재시도, 초안 저장·반영은 업로더만 수행한다. 다른 멤버에게는 초안 편집 화면을 읽기 전용으로 제공한다.
- 반영된 OCR 품목의 이름·단가·수량·삭제는 업로더만 직접 변경한다. 다른 멤버에게는 수정 요청 기능을 제공하고 업로더가 승인·거절한다.
- 수기 품목 편집, 반영된 품목의 참여자·정산 제외, 영수증 이름·결제자·날짜 수정은 방 멤버 누구나 가능하다. 초안 안의 참여자·제외 상태 편집은 초안 저장 권한을 따른다.
- 수기 영수증과 업로더 기록이 없는 기존 영수증의 예외는 최종 설계 §6.1을 따른다. 수기 영수증에는 이미지 추가·OCR 시작 기능을 제공하지 않는다.
- 업로더 탈퇴 시 처리와 영수증 삭제 권한 등의 미결정 사항은 최종 설계 §12를 따른다. 화면에서 임의의 승인자 위임이나 자동 승인을 추가하지 않는다.

## 2. 추출 항목과 데이터 의미

| 항목 | 내부 의미 | 추출·검토 규칙 |
|---|---|---|
| 품목명 | `name` 후보 | 인쇄된 명칭을 보존. 잘린 이름·복수 행 이름은 원문 확인 표시 |
| 단가 | `price` 후보 | 한 개의 가격. 행 금액을 단가로 바로 복사하지 않음 |
| 수량 | `quantity` 후보 | 양의 정수. 누락됐다고 자동으로 1을 넣지 않음 |
| 행 금액 | `lineAmount` 후보 | 사진에 표시된 품목 전체 금액. 단가 × 수량과 별도 보관·비교 |
| 인식 총액 | 사진별 `totalAmount` 후보 | 원본 확인용 읽기 전용 참고값. 공급가액·부가세·카드 결제 일부 금액과 구분. `declaredTotal` 입력으로 사용하지 않음 |
| 상호명 | 영수증 이름 후보 | 선택 보조 항목. 추출 실패해도 사용자가 이름 입력 가능 |
| 거래 날짜 | `purchasedAt` 후보 | 선택 보조 항목. 유효한 날짜인지 검사하고 등록 시각으로 대체하지 않음 |
| 출처 | `imageId`, 이미지 순서, 행 식별자 | 모든 후보에 원본 사진 연결. 공급자가 제공하면 영역 좌표도 유지 |
| 검토 정보 | 필드별 원문·후보 값·신뢰도·검토 사유 | 누락·변환 실패·계산 불일치·중복 의심을 구분 |

카드번호·승인번호·전화번호·사업자번호는 정산에 필요하지 않으므로 내부 정산 모델에 옮기지 않는다. 결제자와 참여자는 사진에서 추측하지 않는다. 이미지 영수증의 결제자는 업로더의 `RoomMember.id`를 기본값으로 표시하며 방 멤버가 변경할 수 있다. 품목 참여자는 사용자가 해당 방의 `RoomMember.id`로 지정한다.

CLOVA가 제공하는 신뢰도는 참고 정보로 보관하며 값이 없으면 `null`로 둔다. 별도 정확도 평가나 신뢰도 임계값 조정은 수행 범위에 포함하지 않는다. 검토 표시는 누락·형식 오류·금액 불일치·중복 의심처럼 명확한 규칙을 기준으로 제공하며 모든 결과는 사용자 확인을 거친다.

## 3. 정규화와 검토 규칙

- 원문과 정규화된 값을 분리한다. 금액의 쉼표·통화 기호는 의미가 명확한 경우에만 제거한다. 숫자와 문자가 섞이거나 해석이 여러 개인 문자열은 검토 대상으로 둔다.
- 빈 값은 `null`로 유지한다. 금액을 0으로 채우거나 수량을 1로 채워 정상 품목처럼 만들지 않는다.
- 행 금액과 수량이 명확하고 나눗셈이 정확한 정수이면 단가를 계산 후보로 제시할 수 있다. `계산으로 추정` 표시와 사용자 확인을 요구하며, 나누어떨어지지 않는 값을 반올림하지 않는다.
- 예를 들어 수량 2, 행 금액 6,000원만 읽혔다면 단가 3,000원을 후보로 표시한다. 수량이 없으면 6,000원을 단가로 확정하지 않는다.
- `단가 × 수량`과 OCR 행 금액이 다르면 둘 다 보여준다. 자동으로 어느 한쪽을 덮어쓰지 않는다.
- 인식 총액 후보가 여러 개면 출처 사진과 함께 읽기 전용으로 보여준다. 후보를 합산하거나 품목 합계로 덮어쓰지 않으며, 별도 총액 선택·입력·확정 기능은 제공하지 않는다.
- 할인·무료 증정·반품·소수 수량은 일반 양수 정수 품목과 구분해 검토 사유를 남긴다. 음수 할인 행이나 차액 맞추기용 임의 품목을 생성하지 않는다.
- 실제 결제된 단가·수량을 원본에서 확인해 공통 계약 안에서 표현할 수 있을 때만 반영한다. 표현할 수 없는 할인·환불 내역은 지원 범위 밖이라고 안내하고 자동 반영을 중단한다.

정상 품목 반영 시 공통 금액 상한을 검사한다. 검사 대상은 단가·수량·계산한 품목 금액과 기존 품목을 포함한 영수증·방 합계이며, 제외 품목도 합계에 포함한다. 인식 총액의 누락·불일치는 품목 반영이나 정산을 차단하지 않는다. `issues`·`warnings`·`blockers`의 구분은 최종 설계 §5.2를 따른다.

## 4. 여러 사진의 결과 결합

1. 업로더가 이미지 목록과 순서를 확인한 뒤 `인식 시작`을 누른다. 작업이 생성되면 이미지 추가·삭제를 잠근다. 사진을 추가할 때마다 전체 OCR을 자동 재실행하지 않는다.
2. 한 사진씩 인식하고 각 결과에 `imageId`를 붙인다. 화면 표시 순서는 이미지 순서와 이미지 안의 행 순서를 따른다.
3. 서로 인접한 사진의 끝·시작 부분에 동일한 품목명·수량·금액 후보가 있으면 `중복 의심`으로 표시한다. 같은 상품을 실제로 여러 번 구매했을 수 있으므로 자동 삭제·합산하지 않는다.
4. 사용자가 두 사진을 비교하여 중복 행 삭제 또는 두 행 유지를 선택한다. 중복 행 삭제와 ‘정산 제외’는 다르다. 정산 제외는 행과 금액이 남으므로 중복 해결에 사용하지 않는다.
5. 사진마다 읽힌 총액은 후보 목록으로 묶고 합산하지 않는다. 동일한 총액이 반복돼도 영수증 전체 총액은 하나다.
6. 일부 사진에서 실패하면 성공 결과를 보존하고, `retryable`인 실패 사진에만 재시도 기능을 제공한다. 재시도 결과는 같은 초안에 추가한다. 보완하지 않은 실패 사진이 남아 있으면 전체 반영을 막는다. 업로더가 해당 사진 범위를 수기로 보완하고 명시적으로 확인할 수 있다.
7. 인식 시작 후 이미지 추가·삭제 요청은 `IMAGES_LOCKED`로 거부한다. 성공 결과를 다시 인식하거나 사진을 교체하려면 새 영수증을 만들어 업로드한다. 남길 수기 품목 이동과 이전 영수증 삭제는 최종 설계 §1·§7의 절차를 따른다. 영수증 하나에 새 작업·새 초안을 반복 생성하지 않는다.

## 5. 인식 결과 수정 화면

### 이미지와 처리 상태

- 데스크톱은 사진과 품목 표를 함께 표시하고, 모바일은 사진·품목 영역을 전환해도 입력값을 유지한다.
- 최대 3장의 썸네일, 업로드 순서, 사진별 처리 상태, 확대·축소 기능을 제공한다. 품목을 선택하면 연결된 사진으로 이동한다. 좌표가 있으면 해당 영역을 표시하고, 없으면 사진 전체를 표시한다.
- 서명 URL 만료 시 이미지 목록을 다시 조회해 갱신한다. 재조회 실패나 권한 상실을 무한 새로고침으로 처리하지 않는다.
- 변환·업로드·인식 중 상태를 구분하고, 실패한 단계와 재시도 방법을 안내한다. 실제 진행률을 알 수 없으면 임의의 완료 퍼센트를 표시하지 않는다.
- 상태 조회는 최종 설계 §5.9의 간격·한도를 따른다. 이전 요청이 끝나기 전에 다음 요청을 보내지 않고, 429 응답 시 조회 간격을 늘린다.

### 품목 편집

- 행별 품목명·단가·수량을 수정하고 행 추가·삭제를 지원한다. 계산 금액과 OCR에서 읽은 행 금액을 구분해서 보여준다.
- 오류는 필드 옆에 구체적인 사유로 표시한다. 색상만으로 구분하지 않고 문구를 함께 제공한다.
- 원문·추정값·사용자 수정값을 구분한다. 인식 행 삭제는 `removed`로 저장해 되돌릴 수 있게 한다. 사용자가 추가한 행은 목록에서 빼면 삭제된다. 실패 사진 재시도로 기존 편집값을 덮어쓰지 않는다.
- 결제자는 영수증 단위, 참여자는 품목 단위로 지정한다. 일괄 참여자 적용은 사용자가 명시적으로 선택했을 때만 수행한다.
- `정산 제외`는 명시적 선택이다. 제외 시 참여자가 해제됨을 안내하고, 다시 포함하면 참여자를 지정하도록 표시한다.
- 이름·결제자·날짜는 초안에 저장하지 않고 기존 영수증 수정 API로 바로 저장한다. 이름·날짜 후보를 채택할 때도 동일하다. OCR 반영은 현재 메타정보를 보존한다.
- 인식 작업이 진행 중이면 초안 저장·반영을 허용하지 않는다. 초안 저장·반영 시 `revision`을 보내고 충돌 시 서버의 최신 초안을 확인하게 한다. 로컬 수정값을 확인 없이 덮어쓰지 않는다.

### 합계와 저장

화면에는 사진별 인식 총액 후보, 제외 품목을 포함한 초안 품목 합계(`itemsTotal`), 후보와의 차이, 정산 대상 금액을 구분해 표시한다. 초안 합계를 기존 수기 품목까지 포함한 영수증 전체 합계로 오해하게 표시하지 않는다. 총액 후보가 있고 어느 후보도 `itemsTotal`과 같지 않으면 `OCR_TOTAL_MISMATCH` 경고를 보여준다. 후보가 없으면 미인식으로 표시하며 총액 입력을 요구하지 않는다.

| 동작 | 허용 조건과 결과 |
|---|---|
| 검토 초안 저장 | 작업 종료 후 편집 중인 초안에 누락·범위 초과 값을 저장 가능. 값의 허용 형식은 최종 설계 §5.4를 따르며 정상 `items`에는 넣지 않음 |
| 영수증에 반영 | 초안 revision 일치, 작업 종료, 실패 사진 보완, 삭제하지 않은 행 1개 이상과 모든 반영 차단 사유 해소, 금액 상한 충족, 전체 검토 확인(`reviewConfirmed`) 필요. 기존 품목에 추가하며 배정·반영 상태를 원자적으로 저장 |
| 총액 누락·불일치 | 그 사유만으로 반영·정산을 막지 않음. 후보 누락 또는 차이를 표시하고 자동 보정하지 않음 |
| 정산 진행 | 결제자·품목별 참여자·금액 등 나머지 정산 조건 충족 필요. 총액 입력·일치는 요구하지 않음 |
| 성공 결과 재인식 | 새 영수증으로 사진을 올려 시작. 실패 사진 재시도와 구분 |
| 화면 이탈 | 저장되지 않은 수정이 있으면 이탈 안내. 마지막으로 저장한 검토 초안은 재접속 시 복구 |

전체 검토 확인 후 초안을 고쳐 저장하면 확인을 해제하고 새 revision에 대해 다시 확인받는다. 행별 확인 상태를 별도로 저장하지 않는다. 중복 의심 행의 ‘둘 다 유지’ 확인은 최종 설계의 `duplicateConfirmed` 규칙을 따른다.

‘OCR 반영 완료’는 ‘송금 정산 가능’과 다른 상태다. 품목이 모두 비어 있는 결과는 `EMPTY_RESULT`로 표시하고 새 영수증으로 다시 올리거나 수기 보완하게 한다. 수정 요청이 대기 중이면 정산 응답의 `holds`로 ‘정산 보류’를 표시하되 계산·공유를 차단하지 않는다. 정산 차단 여부는 `ready`·`issues`로 판단한다.

## 6. 백엔드와 저장소 연결 경계

- 이미지 저장 담당은 이미지 추가·삭제·조회, 장수·형식 검사, 권한 검사와 객체 정리를 제공한다. OCR 담당은 해당 영수증의 이미지 바이트를 서버 내부에서 읽어 공급자에게 전달한다. 프런트엔드가 임의의 외부 URL이나 객체 키를 지정해 OCR을 호출하지 않는다.
- 공급자 호출은 서버에서 수행하며 API 키를 브라우저에 전달하지 않는다. CLOVA 영수증 API에는 파일을 전달하며 서명 URL은 미리보기에만 사용한다.
- OCR 요청·결과·검토 초안은 정상 품목과 분리한다. 작업·이미지 식별자, 사진별 상태, 후보·출처·검토 사유, 초안 `revision`은 최종 설계 §3·§5의 모델과 응답을 사용한다.
- 처리 상태는 `대기 → 처리 중 → 검토 가능 / 일부 실패 / 실패`, 초안 상태는 `편집 중 → 반영 완료`로 구분한다. enum·엔드포인트·오류 사유는 최종 설계를 따른다.
- 동일 작업의 중복 요청과 동일 초안의 중복 반영을 차단한다. 같은 반영 요청은 기존 결과를 반환하고, 같은 식별자로 다른 내용을 제출하면 충돌로 처리한다.
- 공급자 호출 동안 방 DB 잠금을 유지하지 않는다. 반영 시에는 방 잠금 안에서 권한·초안 revision·금액·중복 반영을 검사한다. 이미지 목록은 작업 생성 시 고정하고, 기존 영수증 수정 버전을 별도 반영 조건으로 요구하지 않는다. 기존 메타정보·품목을 덮어쓰지 않고 초안 품목을 추가한다.
- 기존 `/contents`는 정상 품목 전체를 교체하는 API다. OCR 초안을 그대로 이 API에 전달하지 않으며, OCR 확정 서비스가 공통 저장 검증을 재사용하고 중복 반영 방지를 함께 처리하도록 설계한다.
- 타임아웃·일시 오류와 지원하지 않는 입력을 구분한다. 자동 무한 재시도를 하지 않고 실패 상태와 수동 재시도를 제공한다. 재시도는 성공한 사진을 불필요하게 다시 호출하지 않는다.
- 영수증·방 삭제 또는 접근 권한 상실 후 도착한 결과는 반영하지 않는다. OCR 초안과 관련 결과도 영수증 삭제 시 함께 정리한다. 원문 응답과 이미지·서명 URL은 일반 로그에 남기지 않는다.

DB·API 구현과 공통 계약 갱신은 최종 설계 §9·§11의 목록을 따른다. 이 문서는 화면 요구사항이며, 기존 API가 이미 확장되었다는 뜻은 아니다.

## 7. 수용 기준

| 검증 상황 | 기대 결과 |
|---|---|
| 한국어 품목명·수량 2·행 금액 6,000원, 단가 없음 | 계산 후보 3,000원과 추정 표시. 사용자 확인 전 정상 품목 미반영 |
| 수량·금액 누락 또는 범위 초과 | 원문과 오류 유지, 초안 저장 가능, 정상 품목 반영 차단 |
| 사진 경계에 같은 품목 반복 | 양쪽 출처와 중복 의심 표시, 자동 삭제 없음 |
| 3장 중 1장 OCR 실패 | 성공 결과 보존, 재시도 가능한 실패 사진만 재시도, 실패 범위 보완 전 전체 반영 차단 |
| 인식 총액 30,000원·초안 품목 합계 33,000원 | 차이와 `OCR_TOTAL_MISMATCH` 경고. 다른 반영·정산 조건 충족 시 진행 가능 |
| 인식 총액 없음 | 미인식 표시. 총액 입력을 요구하거나 그 사유로 반영·정산을 차단하지 않음 |
| 실패 사진 재시도 | 성공 사진은 재호출하지 않고 기존 편집값 유지 |
| 성공 결과 재인식 | 같은 영수증에 새 작업 생성 불가. 새 영수증으로 업로드 안내 |
| 반영 버튼 중복 클릭·응답 유실 후 재시도 | 품목 중복 생성 없음 |
| 인식 시작 후 이미지 추가·삭제 | 기능 잠금 표시, 서버는 409 `IMAGES_LOCKED` |
| 검토 중 영수증 이름·결제자·날짜 수정 | 즉시 별도 저장, OCR 반영 뒤에도 변경값 유지 |
| 검토 확인 후 초안 수정·저장 | 확인 해제, 새 revision에 대한 전체 검토 확인 필요 |
| 업로더가 아닌 멤버의 초안 접근 | 조회만 허용. 편집·반영 불가 |
| 다른 멤버가 반영된 OCR 품목 금액을 수정하려 함 | 직접 수정 대신 수정 요청 제공 |
| 대기 중인 수정 요청 | 정산 보류 표시. `holds`만으로 정산 계산·공유 차단하지 않음 |
| URL 만료 | 권한 확인 후 새 URL 발급, 초안 편집값 유지 |
| 비멤버·공유 토큰으로 이미지 또는 초안 접근 | 접근 거부 |
| OCR 반영 완료 | 사진 유지, 이미지 개별 삭제는 계속 잠금. 영수증·방 삭제 시 관련 데이터·객체 정리 |
