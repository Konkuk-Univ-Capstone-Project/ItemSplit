# CLOVA OCR 연동 설계

이 문서는 CLOVA 호출·응답 매핑·공급자 오류 처리를 정의한다. OCR 정책·DB·API의 최종 기준은 [OCR 상태·DB·API 최종 설계](state-db-api-design.md)이며, 화면 동작은 [추출·수정 화면 요구사항](ocr-extraction-review-requirements.md)을 따른다. 설계 채택은 구현 완료를 뜻하지 않는다.

## 1. 사용 서비스와 범위

한국어 영수증 인식에는 NAVER CLOVA OCR의 영수증 특화 API를 사용한다. 품목명·수량·단가·행 금액·총액을 구조화된 응답에서 추출해 프로젝트의 검토 초안으로 변환한다.

서비스 선정은 CLOVA 사용을 전제로 하며, 공급자 비교·영수증 샘플 수집·정답 데이터셋 구축·정확도 벤치마크는 수행 범위에서 제외한다. 이 문서의 구현 범위는 API 연결, 내부 후보로의 응답 매핑, 공급자 오류 처리 및 연동 검증이다. 작업·초안 저장과 정상 품목 반영은 최종 설계의 OCR 서비스가 담당한다.

[공통 계약](../api-db-contract.md)의 금액 상한·멤버 ID·원자적 저장 규칙을 재사용한다. 별도 총액 입력 제거·OCR 총액 경고 정책은 공통 계약과 일치하며 수정 권한은 최종 설계의 변경안을 우선한다. 이미지 저장은 [S3 저장 설계](../storage/image-storage-design.md)를 따른다. 인식 결과는 사용자 확인 없이 정상 품목으로 반영하지 않는다.

## 2. 입력과 호출 방식

| 항목 | 설계 기준 |
|---|---|
| 입력 형식 | 서비스 업로드 형식은 JPEG·PNG |
| 기타 이미지 | HEIC·HEIF·WEBP는 화면에서 JPEG로 변환 후 업로드 |
| 크기·장수 | 장당 최대 10MB, 같은 영수증 최대 3장. 외부 API의 별도 제한도 구현 시 확인 |
| 호출 위치 | 백엔드에서 호출. 브라우저에 API 인증 정보를 전달하지 않음 |
| 전달 방식 | 서버가 이미지 바이트를 읽어 `multipart/form-data`로 한 장씩 전달 |
| 호출 시작 | 이미지 업로드를 마친 뒤 사용자가 인식 시작 선택 |
| 결과 연결 | 작업 ID와 `imageId`를 연결하고 업로드 순서 유지 |
| 이미지 보관 | OCR 완료 여부와 무관하게 S3 설계의 삭제 정책을 따름 |

영수증 API는 파일 또는 Base64 입력을 지원하며 이 설계에서는 파일 전달을 사용한다. S3 서명 URL은 화면 미리보기에 사용하고, General OCR의 URL 입력 지원을 영수증 특화 API에도 적용된다고 가정하지 않는다. [CLOVA 영수증 API](https://api.ncloud-docs.com/docs/ai-application-service-ocr-ocrdocumentocr-receipt)

HEIC 변환 도구, JPEG 품질 및 리사이즈 설정은 이미지 업로드 구현에서 정한다. 별도 정확도 비교 실험은 계획하지 않으며, 변환 후 방향·미리보기·크기 제한은 업로드 기능의 동작 확인 항목으로 둔다.

## 3. 응답과 내부 데이터 매핑

아래 경로는 `receipt.result` 아래의 응답 필드를 기준으로 한다. 각 객체의 인식 원문과 정규화 값을 구분해서 읽는다.

| CLOVA 응답 | 내부 초안 | 처리 기준 |
|---|---|---|
| `subResults[].items[].name` | 품목명 후보 | 원문을 유지하고 사용자가 수정 가능 |
| `subResults[].items[].count` | 수량 후보 | 양의 정수인지 확인, 누락 시 `null` |
| `subResults[].items[].price.unitPrice` | 단가 후보 | 한 개 가격으로 해석 |
| `subResults[].items[].price.price` | 행 금액 후보 | 단가 × 수량과 별도 비교 |
| `totalPrice.price` | 사진별 `totalAmount` 후보 | 읽기 전용 참고값. 사진별 총액을 합산하거나 품목 합계로 덮어쓰지 않음 |
| `storeInfo.name` | 영수증 이름 후보 | 선택 보조 정보 |
| `paymentInfo.date` | 거래 날짜 후보 | 유효한 날짜인지 확인 |
| 필드별 신뢰도·좌표 | 검토 참고 정보 | 제공된 경우 보존, 없으면 비워 둠 |

응답 구조는 [공식 영수증 API 문서](https://api.ncloud-docs.com/docs/ai-application-service-ocr-ocrdocumentocr-receipt)를 따른다. 응답 필드가 없거나 숫자로 해석되지 않으면 정상값을 만들어 넣지 않고 검토 사유를 남긴다. 카드번호·승인번호 등 정산과 무관한 정보는 내부 품목 모델에 옮기지 않는다.

CLOVA 응답을 `items`에 직접 저장하지 않는다. 최종 설계 §8의 `ReceiptOcrEngine` 구현체는 이미지 한 장을 내부 후보로 변환하며 DB와 사용자 권한을 다루지 않는다. OCR 서비스가 필드별 원문·신뢰도·좌표와 후보를 저장하고, 공급자 전체 응답은 저장하지 않는다. 결제자·품목 참여자는 OCR로 추정하지 않는다. 이미지 영수증의 결제자 기본값은 생성 단계에서 업로더의 방 멤버로 설정하며 이후 변경할 수 있다.

## 4. 처리 흐름

1. OCR 서비스가 방 멤버·업로더 권한, 이미지 영수증 여부, 기존 작업과 호출 한도를 검사한다. 작업 생성 후 이미지 추가·삭제를 잠그고 비동기로 처리한다.
2. 작업 스레드가 고정된 이미지 목록의 순서대로 바이트를 읽는다. 공급자 호출 중에는 DB 트랜잭션·잠금을 유지하지 않는다.
3. CLOVA에 한 장씩 전달하고 응답 성공 여부를 확인한다. HTTP 성공만으로 인식 성공이라고 판단하지 않고 `inferResult`도 확인한다.
4. 엔진은 원문과 정규화 값을 구분한 후보를 반환한다. 없는 값은 `null`로 유지한다. 단가 계산 후보는 편집값에 자동 반영하지 않는다.
5. OCR 서비스가 사진별 상태와 초안을 저장한다. 인식 품목이 없으면 `EMPTY_RESULT`로 처리한다. 사진 경계의 중복 의심 판정은 엔진 밖에서 수행하며 자동 삭제·합산하지 않는다.
6. 업로더가 품목을 검토·수정해 초안을 저장하고 `revision`과 `reviewConfirmed`로 반영을 요청한다. 이름·날짜 후보를 채택하는 작업은 기존 영수증 수정 API로 별도 저장한다. 총액 입력·수정은 제공하지 않는다.
7. OCR 서비스는 최종 설계 §5.5에 따라 방 잠금 안에서 반영 조건을 검사하고 초안 품목·배정을 기존 영수증에 추가한다. 기존 품목·메타정보를 덮어쓰지 않으며 반영 상태와 함께 원자적으로 저장한다.

OCR 총액 후보의 누락·불일치는 반영이나 정산을 차단하지 않는다. 불일치는 `OCR_TOTAL_MISMATCH` 경고로 제공한다. `itemsTotal`은 삭제하지 않은 초안 행 중 단가·수량이 있는 행의 합계이며 정산 제외 품목도 포함한다. 제외 선택만으로는 불일치가 생기지 않고 삭제한 행은 합계에서 빠진다. OCR의 품목 누락·오인식, 수량·가격·할인 인식 오류 또는 사용자의 초안 추가·수정·삭제로 총액 후보와 차이가 생길 수 있다. `OCR_TOTAL_MISMATCH`는 확인을 돕는 경고이며 반영·정산을 차단하지 않는다. 품목 금액 상한·참여자·결제자 등 나머지 검증은 유지하므로 OCR 반영 완료가 정산 가능을 뜻하지는 않는다.

## 5. 오류·재시도·설정

| 상황 | 처리 |
|---|---|
| 인증·설정 오류 | `CONFIG_ERROR`. 일반 재시도 불가, 서버 설정 확인. 인증 정보는 노출하지 않음 |
| 타임아웃·호출 제한·일시 오류 | `TIMEOUT`·`RATE_LIMITED`·`PROVIDER_ERROR`. 실패 상태로 기록하고 수동 재시도 허용. 자동 재시도하지 않음 |
| 인식 실패·빈 품목 | `RECOGNITION_FAILED`·`EMPTY_RESULT`. 같은 사진의 재시도 불가. 새 영수증으로 다시 올리거나 수기 보완 안내 |
| 일부 사진 실패 | 성공 결과·기존 편집값 보존. 재시도 가능한 오류의 실패 사진만 같은 작업·초안에 추가 |
| 성공 결과 재인식 | 영수증당 작업 하나이므로 새 영수증으로 사진을 올려 시작. 같은 영수증의 새 작업은 `JOB_ALREADY_EXISTS` |
| 인식 시작 후 이미지 변경 | 추가·삭제 요청을 `IMAGES_LOCKED`로 거부 |
| 검토 중 영수증 메타정보 변경 | 허용. 초안은 품목만 담고 반영 시 현재 메타정보를 보존 |
| 중복 반영 요청 | 이미 반영한 revision이면 현재 영수증 상세 반환, 다른 revision이면 충돌. 품목 중복 생성 방지 |

호출 주소·인증 키·타임아웃·합성 응답용 `fake` 구현체는 최종 설계 §4의 설정을 따른다. 서비스 내부 호출 한도와 집계는 최종 설계 §5.8을 따른다. 공급자 호출은 사진 단위이며 재시도도 집계한다.

사진 한 장의 최초 시도와 재시도를 합쳐 최대 3회(최초 1회 + 재시도 최대 2회)이며 날짜가 바뀌어도 초기화하지 않는다. 재시도 가능한 오류로 실패한 사진만 다시 호출하고 성공한 사진은 재호출하지 않는다. 일일 한도는 공급자에 보내는 사진당 1회로 계산해 영수증당 15회, 요청 사용자당 60회이며 한국 시간(`Asia/Seoul`) 자정에 새 날짜로 집계한다. 같은 시작 요청이나 이미 대기·처리 중인 재시도 요청의 중복 전송에는 추가 차감하지 않는다.

여러 사진의 필요 횟수를 DB에서 한 번에 예약하고 부족하면 전체 요청을 HTTP 429로 거부한다. 사유는 `OCR_RECEIPT_DAILY_LIMIT` 또는 `OCR_USER_DAILY_LIMIT`이다. 공급자를 호출하기 전에 실패한 사진은 최초 예약 날짜의 횟수를 반환하며, 공급자 호출 후 실패(공급자가 반환한 `UNSUPPORTED_INPUT` 포함)는 사용량에 남는다. 호출 직전 전달 상태를 기록한 이후의 서버 중단도 보수적으로 사용량에 포함한다. DB 사용량은 영수증·작업 삭제나 서버 재시작으로 초기화되지 않는다.

현재 영수증당 최대 3장 × 사진당 최대 3회이므로 한 영수증에서 도달 가능한 누적 시도는 최대 9회다. 일일 15회는 추가 안전장치이며 기본 흐름에서는 도달하지 않는다. 영수증 일일 한도 테스트는 설정값을 낮추거나 사용량 예약 계층을 직접 검증한다. 서비스 전체 일일 상한과 별도 상태 조회 제한은 설계 범위로 남아 있다.

 실제 공급자 제한과 요금은 사용하는 도메인의 계약 조건을 확인한다. [CLOVA 상품·요금 안내](https://www.ncloud.com/product/aiService/ocr)

작업 ID·처리 상태·오류 코드·소요 시간·호출 횟수를 운영 기록으로 남긴다. 이미지 바이트·인증 키·서명 URL·민감한 OCR 원문은 일반 로그에 남기지 않는다.

## 6. 구현 완료 확인 기준

공급자 어댑터와 OCR 서비스의 연결을 확인한다. 기본 자동 테스트는 합성 응답으로 수행하고, 실제 외부 호출은 배포 환경의 연결 확인으로 구분한다. 화면 수용 기준은 별도 요구사항 문서를 따른다.

- 정상·누락·잘못된 숫자가 포함된 응답을 초안에 올바르게 매핑한다.
- 단가와 행 금액을 혼동하지 않고 총액·수량 누락을 임의로 채우지 않는다.
- 이미지 3장의 순서·출처를 보존하고 일부 실패를 개별 재시도할 수 있다.
- 오류 응답·타임아웃·빈 결과를 사용자에게 설명한다.
- 실패 사진 재시도로 기존 편집값이 사라지지 않으며 성공 사진을 다시 호출하지 않는다.
- HTTP 성공과 인식 성공을 구분하고, 품목이 없는 응답은 `EMPTY_RESULT`로 처리한다.
- 총액 후보는 사진별 참고값으로 전달하며 품목 합계를 맞추기 위해 변조하지 않는다. 총액 불일치는 경고이고, 금액 상한·참여자 검증은 OCR 서비스가 최종 설계에 따라 수행한다.
- 배포 환경에서 API 인증·파일 전달·응답 수신부터 수정 화면 표시까지 연결을 확인한다. 별도 샘플 수집 수량이나 정확도 목표는 두지 않는다.
